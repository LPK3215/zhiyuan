# 志愿填报技能

当用户咨询高考志愿填报相关问题时使用此技能：包括查分数、算位次、推荐院校、对比专业、检索政策、生成志愿方案。

## 可用工具

- `search_universities`：搜索院校列表，支持按关键词、省份、层次、类型筛选。
- `get_university_detail`：查院校基本信息（层次、类型、硕博点、重点学科）及开设专业。
- `query_admission_scores`：查院校/专业历年录取分数线和位次。
- `estimate_rank`：根据分数查一分一段表获取位次（全省排名）。
- `generate_plan`：生成冲稳保三档志愿方案，含概率分析。
- `compare_universities`：对比多所院校的录取数据和专业设置。
- `query_knowledge_graph`：查询知识图谱（院校-专业-学科-职业关系）。
- `search_policy`：搜索高考政策、院校招生政策相关信息。
- `analyze_admission_probability`：分析用户被指定院校录取的概率。
- `recommend_majors`：根据分数和兴趣推荐适合的专业。
- `get_system_status`：查询系统运行状态和数据概览。

## 操作流程

1. 确认用户三要素：省份、科类（或选科组合）、分数。缺任何一个必须追问。
2. 有分数后立即调 `estimate_rank` 获取位次，位次是后续所有推荐的基准。
3. 推荐院校时调 `generate_plan`，必须附位次对比数据。
4. 用户问"能不能上XX"时调 `analyze_admission_probability` 综合判断。
5. 政策类问题（如平行志愿规则、投档比例）调 `search_policy` 检索，禁止凭记忆回答。
6. 用户明确要"出方案"/"生成志愿表"时调 `generate_plan`。
7. 用户想对比院校时调 `compare_universities`。
8. 用户想了解专业方向时调 `recommend_majors`。

## 关键约束

- 推荐前必须已有 rank（位次），没有就先查。
- 政策信息必须走工具检索，不得编造。
- 推荐必须附数据依据（位次、概率、趋势），不能只给名字。
- 工具查不到数据就说"暂无数据"，绝不编造分数或位次。
- 方案生成后自检：志愿数量是否符合省份规则、有无选科冲突、冲稳保比例是否合理（建议2:3:2或3:3:3）。
- 新高考省份注意选科限制，推荐前先确认选科信息。
